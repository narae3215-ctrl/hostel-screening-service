# 공공데이터·외부 API 활용 약관 검토 (WBS 8.3)

> API별 이용약관·출처표시 의무를 확인하고, Phase 3(공공데이터 연동) 개발 시 반드시 지켜야 할 조건을 정리한다. 본 서비스가 실제로 사용할 API는 국토교통부 건축물대장정보/건축인허가정보, 토지이용계획(공공데이터포털 또는 브이월드), 카카오맵/로컬 API 3종이다.

## 1. 공공데이터포털(data.go.kr) — 공공누리(KOGL) 라이선스 체계

공공데이터포털에 등록된 공공데이터(건축물대장정보, 건축인허가정보 등)를 활용할 때에는 「저작권법」에 따른 **공공누리(KOGL) 유형**이 부착되어 있으며, 이용자는 해당 유형의 조건을 지켜야 한다. data.go.kr 이용약관은 "저작물이 포함된 공공데이터를 제공할 때에는 관련 법령에 따른 공공누리 유형을 부착하여 공공데이터의 이용허락 범위를 표시해야 한다"고 명시한다.

### 공공누리 유형별 조건

| 유형 | 출처표시 | 상업적 이용 | 변경(2차 저작물 작성) |
|---|---|---|---|
| 제1유형 | 필수 | 가능 | 가능 |
| 제2유형 | 필수 | **불가(비영리만)** | 가능 |
| 제3유형 | 필수 | 가능 | **불가(원본 그대로만)** |
| 제4유형 | 필수 | **불가** | **불가** |

**실행 항목:**
- Phase 3에서 실제로 신청할 각 API(건축물대장정보 서비스, 건축인허가정보 서비스)의 상세페이지에서 부착된 공공누리 유형을 반드시 확인한다. 대부분의 국토교통부 표준 오픈API는 제1유형(출처표시)으로 공개되는 경우가 많지만, **API별로 다를 수 있으므로 API 키 발급 시 표시되는 유형을 그대로 따른다.**
- 본 서비스는 대장 원본 데이터를 가공(면적 계산, 판정 로직 적용)해 새로운 결과물(스크리닝 리포트)을 만들어 상업적으로 제공할 계획이므로, **제2·제4유형(비영리 전용)에 해당하는 데이터셋은 사용할 수 없다.** API 신청 전에 유형을 확인하고 제1유형 또는 제3유형(가공 없이 원본만 노출하는 화면에 한해) 데이터만 채택한다.
- 출처표시 문구 예시(화면 하단 또는 데이터 출처 안내 영역에 고정 노출):
  > 본 서비스는 국토교통부 건축물대장정보 서비스, 토지이용규제정보서비스(공공데이터포털) 등 공공데이터를 활용하여 제작되었습니다. (출처: 공공데이터포털, data.go.kr)

### 이용 신청 관련 유의사항

- 활용신청 시 "활용목적", "예상 트래픽" 등을 정확히 기재해야 하며, 승인 후 목적 외 용도(예: 대량 크롤링·재판매)로 사용하면 이용정지 사유가 될 수 있다.
- API 트래픽 제한(일일 호출 한도)이 있으므로 Phase 3.7(API 응답 캐싱 레이어)이 반드시 함께 구현되어야 한다 — 단순 성능 개선이 아니라 **약관 준수(과도한 반복 호출 금지) 관점에서도 필수**다.

## 2. 토지이용계획 관련 정보 (토지이음/브이월드)

현재 서비스 설계상 "2단계: 토지이음 조회 인계"는 사용자가 직접 eum.go.kr을 조회하도록 안내하는 방식(스크리닝 스킬의 조회 지시문 생성)으로 되어 있어, 이 단계는 API 약관 이슈가 발생하지 않는다(자동 스크래핑이 아니라 사용자가 직접 웹사이트를 열람).

향후 이 단계를 브이월드(V-World) 토지이용규제 API 등으로 자동화한다면, 브이월드 역시 공공데이터포털과 유사하게 공공누리 유형을 따르므로 위 1항과 동일한 절차(유형 확인 → 상업적 이용 가능 유형만 채택 → 출처표시)를 적용한다.

## 3. 카카오맵 / 카카오 로컬 API

카카오 디벨로퍼스 플랫폼(developers.kakao.com)의 지도(Map)·로컬(Local, 주소-좌표 변환) API를 사용할 계획이다. 확인 결과, 카카오는 별도의 "운영정책"(developers.kakao.com/terms/ko/site-policies)을 통해 서비스 이용 시 준수사항을 규정하고 있으나, 지도 출처표시·상업적 이용 관련 세부 조항은 API 콘솔에서 애플리케이션 등록 시 동의하는 개별 이용약관 및 API별 가이드 문서에 있다.

**확인 필요(자동 조회로 원문 확보 실패 — 개발 착수 전 재확인 필수):**
- 카카오맵 JS SDK로 지도를 표시할 때 카카오 로고/저작권 표기를 임의로 제거할 수 없다는 것이 일반적인 지도 API 관행이며, 카카오맵 API도 동일 원칙을 따를 가능성이 높다. **Phase 3.2(카카오맵 API 키 발급) 시점에 카카오 디벨로퍼스 콘솔에 게시된 최신 "지도 서비스 약관" 원문을 반드시 다시 확인**하고, 지도 위젯에 로고 노출 여부를 코드 리뷰 항목에 포함한다.
- 무료 티어의 일일 호출 한도, 상업 서비스 전환 시 유료 플랜 필요 여부도 API 키 발급 시점에 재확인한다.
- 지도 타일 이미지를 서버에 캐싱해 재배포하는 행위는 일반적으로 지도 API 약관에서 금지되는 경우가 많으므로, 캐싱 레이어(3.7)를 설계할 때 **지도 타일/좌표 변환 결과는 캐싱하지 않거나 카카오 약관이 허용하는 범위 내로 한정**한다. (건축물대장 등 순수 공공데이터 캐싱과는 분리해서 다룰 것.)

## 4. 종합 실행 체크리스트 (Phase 3 착수 전)

- [ ] 국토교통부 건축물대장정보/건축인허가정보 API 신청 화면에서 공공누리 유형 스크린샷 확보 및 본 문서에 기록
- [ ] 제2·4유형(비영리 전용)이 아닌지 확인 — 해당되면 대체 데이터 소스 검토
- [ ] 서비스 화면 하단에 공공데이터 출처표시 문구 고정 배치 (프론트엔드 Footer 컴포넌트, 아직 미구현)
- [ ] 카카오 디벨로퍼스 콘솔에서 애플리케이션 등록 시 동의한 최신 약관 원문 PDF/캡처 보관
- [ ] 지도 로고/저작권 표기 유지 여부 코드 리뷰 체크리스트에 추가
- [ ] API별 일일 트래픽 한도 확인 후 3.7 캐싱 레이어 TTL 설계에 반영
- [ ] 최종 게시 전 법률 전문가 검토 (본 문서는 법률 자문이 아님)
